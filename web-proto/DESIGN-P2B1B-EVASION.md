## 1. 目标与边界（先说清不做什么）

**阶段目标**：检验「主持搪塞轴」是否给欺骗环境带来 B-1 缺失的**可学结构**。
B-1 的结论是环境战略空间稀薄：主持除 truth=是 翻转更伤的弱不对称外无可学
结构，提问者唯一反制（冲突丢弃）理性地不值得用。B-1b 引入主持的第二个
决策轴——**搪塞**（对可决策问题给无信息回答）——并配平提问者侧的新决策
（**转化**：复问被搪塞的问句），检验两个可证伪问题：

- **Q1（主持侧）**：训练主持的搪塞**分配**（把 k_e 次搪塞花在哪些问题上）
  是否比随机分配更高效（每搪塞 F1 伤害）？
- **Q2（提问者侧）**：提问者是否学到**非平凡的转化行为**（对「被搪塞的
  问句」与「已被回答的问句」采取不同的复问率）？B-1 的提问者对谎言
  **零反制**（复问率恒 0.000），转化是第一个候选反制。

**明确不做**（防范围蔓延）：

| 不做 | 理由 |
|---|---|
| 改 B-1 的 `DeceptiveHost` / 已有基线 / 已有报告数字 | B-1 负结果是已发布资产，新轴用新类实现，旧类逐位冻结 |
| λ 与 ε 双扫描全交叉 | 本阶段处理是搪塞轴；λ 固定在 B-1 的活跃值 0.01，λ×ε 交互留作后续（§7） |
| 提问者「质疑/挑战」动作（辩论维度） | 属另一条线（mcp-server 的 debate 比较制），本引擎不引入 |
| 跨模型 / LLM 主持 | B-1b 仍是表格 Q 双智能体；LLM 主持是 B-1 文档 §11 所指的另一个方向 |

## 2. 为什么是「搪塞」，以及它必须满足的三条机械学约束

B-1 的谎言轴有三个结构性弱点，搪塞轴的设计逐条对应：

| B-1 弱点 | 搪塞轴的对应设计 |
|---|---|
| 谎言只发生在可决策问题上，且**每次谎言的 tdhit 伤害恒等于 1/R**（§6-A 发现 1）——分配问题无纹理 | 搪塞的伤害机制不同：它**推迟/否认**一次回答，伤害取决于提问者是否转化（§3.3），不是恒等式 |
| 提问者对谎言的反制（复问+冲突丢弃）**理性地不值得用**（§6-A 发现 3：复问 ≤0.5/问 vs 新问 0.75/问）⇒ 零反制 | 搪塞给提问者一个**新的可选动作**：转化被搪塞的问句。其价值结构（§3.4）与复问被谎问句不同 |
| 主持侧除 truth=是 翻转更伤的弱不对称外，分配问题退化 | 搪塞与谎言是**两种资源**（独立配额），且「先搪塞、转化时说谎」构成二阶组合（§3.5） |

**三条机械学约束**（缺任何一条，实验都会以不同方式退化为占优策略）：

1. **独立配额 k_e**。搪塞不可无限——否则「永远搪塞」是无成本占优策略
   （与 B-1 谎言配额同理，配额是让「花在哪些问题上」成为真问题的最小约束）。
2. **同一问句不得二次搪塞**。被搪塞过的问句再次提出时，主持**必须**给
   是/否 回答（诚实或说谎，说谎仍受谎言配额约束）。物理动机：对同一个
   问题两次顾左右而言他是透明荒谬的。没有这条，搪塞就是纯粹的否认工具，
   「搪塞到底」仍占优；有了这条，搪塞是**延迟**工具，提问者保有转化权。
3. **搪塞答案必须与「无关」（不可解析）可区分**。提问者要能判断「这个
   问题是被搪塞了（可以转化）」还是「这个问题没有真值（转化也无用）」。
   故搪塞答案是独立词表 `EVASIVE_ANSWERS = ("与此无关",)`，与既有
   `UNINFORMATIVE_ANSWERS = ("无关", "不重要")` 分开维护——把两者混在
   一个元组里正是本项目反复批评的「口径漂移」形态。

## 3. 游戏设计：三动作 · 双配额 · 转化

### 3.1 主持动作与约束

每个**可决策**问题（truth ∈ {是,否}）三选一：

| 动作 | 效果 | 成本 | 配额 |
|---|---|---|---|
| `truth` (0) | 如实答 | — | — |
| `lie` (1) | 反转答案 | λ（每谎） | 谎言配额 k（默认 2） |
| `evade` (2) | 答「与此无关」 | ε（每次） | 搪塞配额 k_e（默认 2） |

- 不可决策问题（parse 不出类别）：答「无关」，**不构成决策**，不进训练
  轨迹（与 B-1 的 `_decidable_truth` 守卫一致）。
- **配额强制**：策略选了 infeasible 动作（谎言配额耗尽选 lie / 搪塞配额
  耗尽或该问句已被搪塞过选 evade）→ 强制执行 truth，且 Q 更新记录的是
  **执行**的动作（on-policy，与 B-1 同一纪律——用未执行动作的回报去更新
  它等于把探索噪声写进策略）。
- 基线 `RandomEvaderHost`：同 k_e，搪塞位置在「可决策且未被搪塞过」的
  问题上均匀随机，不说谎（E1b 的关键对照，与 B-1 的 random-liar 对位）。

### 3.2 主持状态（题目无关，B-1 承诺不变）

```
state = f"{truth}|{round}|{lie_left}|{evade_left}|{asked_before}|{evaded_before}"
  truth         当前问题的如实答案（是/否）
  round         第几轮（transcript 问题数推得）
  lie_left      剩余谎言配额（k..0）
  evade_left    剩余搪塞配额（k_e..0）
  asked_before  该问句此前是否问过（0/1）
  evaded_before 该问句此前是否被搪塞过（0/1）——约束 2 的状态支撑
```

状态空间 2×8×3×3×2×2 = 576，三动作。**仍然刻意不含题目 ID**：迁移能力
来自构造而非祈祷（B-1 §3.2 承诺，本条不改）。

### 3.3 奖励（零和镜像 + 双成本）

```
提问者单步：转化问句（曾被搪塞）且得到是/否 → +1.0（复问惩罚豁免，见 §3.4）
            真复问（曾被回答）→ −0.5（不变）
            无信息（含搪塞答案）→ −0.2（不变）
            有信息 → +1.0（不变）
主持每步：  = −提问者当步奖励 − λ·[lie] − ε·[evade]
主持终局：  = −2×F1_提问者（不变）
```

**预注册的经济学分析**（先算后跑，防事后解释）：

- 主持每步在「允许真实回答」与「搪塞」之间的收益差 = 1.2 − ε
  （真实回答让提问者 +1.0，搪塞让提问者 −0.2，镜像差 1.2）。
  **只要 ε < 1.2，搪塞在每步意义上占优**——与 B-1 的 λ 尺度（≤0.05）
  完全不可比。故 ε 扫描区间必须跨到 1.2 附近才有「处理未激活」区间
  （§5），这是与 B-1 λ 扫描区间不同的原因，不是疏忽。
- 若提问者以概率 c 转化，则「搪塞后被转化」的主持两步合计
  = (0.2−ε) + (−1.0−λ) = −0.8−ε−λ，仍优于直接回答的 −1.0−λ
  **当且仅当 ε < 0.2**。⇒ ε≈0.2 是「搪塞是否经得起全额转化」的边界，
  与 c 无关。扫描区间 {0, 0.01, 0.05, 0.2, 0.6, 1.3} 同时覆盖
  「免费」「经得起转化」「经不起全额转化但仍是好买卖」「每步意义被压制」
  四档。
- **预测（pre-declared，可被证伪）**：在 ε < 0.2 区间，训练主持将
  **花光搪塞配额**（搪塞数 = k_e），E1b 的「分配效率」很可能接近随机
  ——因为每步收益与问题无关（1.2−ε 是常数），分配价值只通过提问者的
  转化模式与 F1 二阶体现。这正是失败模式 ①b（§6），出现时照实报，
  **不解释成「训练失败」**。

### 3.4 提问者侧：转化（B-1b 的真正新决策）

**转化** = 复问一个**曾被搪塞**的问句。规则：

- 转化成功（得到是/否）→ 单步奖励 **+1.0**（复问惩罚 −0.5 **豁免**）。
  理由：该问句从未得到过回答，「复问刷哨」惩罚的立法目的（惩罚无新信息
  的重复）不适用于它；且 round 的机会成本已由「少问一个新类别」内生承担。
- 转化失败（主持再次搪塞）→ 结构上不可能（约束 2）；若发生（如第三方
  主持违规），按无信息 −0.2 处理，不奖励。
- 真复问（该问句曾得到是/否）→ −0.5 不变。

**终局还原必须区分「无答案」与「矛盾答案」**（实现期最容易踩的坑）：

`final_guess` 现行逻辑「所有回答均为确认才采纳」会把搪塞答案
（非确认）误判成矛盾 → **转化成功后类别反被丢弃**，转化永远无产出。
修正：**搪塞答案在确认判定中被忽略**（它不是答案，不是矛盾）。

- **向后兼容可证明**：无搪塞的对局不存在搪塞答案，该修正是恒等变换
  ——B-1 全部基线数字不变（固化为测试断言，含跨种子验证）。
- 修正后各类别结局（truth=是 为例）：
  - 搪塞→转化→诚实答是：采纳（花 2 轮拿到 1 条真线索）；
  - 搪塞→转化→谎答否：不采纳（且**只有一个是/否 答案，无冲突可查**——
    需第三问才能抓，这是 §3.5 的「安全谎窗口」）；
  - 搪塞→不转化：不采纳（否认成功）。

提问者状态增加 ev 分量（§4），使「转化被搪塞问句」与「复问已回答问句」
在 Q 表中可区分——这是 B-1 缺失的、提问者侧第一个可能 non-trivial 的
决策依据。

### 3.5 二阶组合：先搪塞、转化时说谎（安全谎窗口）

约束 2 让「被搪塞过的问句」只能得到一个是/否 答案。若它是谎言：

- 直接谎言可被「复问+诚实」的冲突丢弃抓住（[否,是] → 矛盾 → 丢弃）；
- 搪塞→谎言只有 [与此无关, 否]，**没有第二个是/否 可供冲突**——
  提问者要花**第三问**才能复现冲突。

即：**搪塞给谎言提供了一次「首击豁免」**。这是本设计预期的核心涌现结构：
主持的分配问题从「谎言花在哪」升级为「哪个问句值得用搪塞垫一刀再谎」。
E1b 与共演轨迹就是观察这个结构是否被学出来（也可能没有——照实报）。

不转化）。**不为了凑正结果改判据**——判据以本文档为准，改动必须留
git 历史（B-1 §6 原文同此纪律）。

**判据必须过「非退化」自检**（项目第三次教训：预注册判据本身可能退化）：
- E1b 的基线是 **random-evader 的每搪塞伤害**，不是「truthful 减去
  trained 再除以搪塞数」——后者在 random 参照下是同一定价，不会恒等，
  但要用 sanity 小规模**实测确认两组数字不同」**（判据退化的前两役

- E2b 的分子分母都必须非零才有判定意义；被搪塞问句数为 0 时判 N/A
  （处理未激活），**不判 0/0=通过**。

## 6-A. 失败模式（pre-declared，出现时对号入座）

1. **①b 主持退化为「有配额就搪塞」**：ε < 0.2 时搪塞数 = k_e 且位置分布
   均匀（诊断：搪塞位置直方图；与 random-evader 的分布距离）。此时
   E1b ≈ 0 是**预期结果**，对应 §3.3 的预测，不是 bug。
2. **②b 提问者永不转化**：转化率恒 0 ⇒ E2b 负。诊断：对比「被搪塞问句」
   与「已回答问句」的复问率——若两者都恒 0，是 B-1 失败模式 ⑤ 的重演
   （信号弱）；若仅被搪塞问句复问率为 0 而已被问答句有复问，则是
   「理性不转化」，解释不同，必须分开报。
3. **③b 共演震荡**：Phase C 轨迹循环追逐（同 B-1 模式 ③）。
4. **④b 12 题过拟合**：held-out 与训练集结论反向 ⇒ 以 held-out 为准
   （双方状态均题目无关，但仍复核）。
5. **⑤b 信号弱**：Q-adv 与 Q-honest 在所有单元格无差别。
6. **⑥b 搪塞完全不激活**：ε ≥ 1.2 区间搪塞数 0（§3.3 预言）⇒ E1b/E2b
   在该区间判 N/A，区间图照实报「处理未激活」（与 B-1 λ=0.05 恒真同形态）。

## 6-B. 指标口径警示（实现与读报告都要守）

- **tdhit 每搪塞伤害在无转化区间是恒等式 1/R**：搪塞答案不进分子、
  问句进分母，且首答去重（setdefault）使复问不改变分子——与 B-1
  谎言的恒等式同构（证明见 tests/test_evade_host.py 固化）。故 E1b
  主判据用 F1，tdhit 仅存档。
- **tdhit 对「转化」的伤害大于恒等式**（测试期发现，跑前留痕）：tdhit
  只取每问**首次**答案，复问拿到的真实答案是/否 对它不可见，而提问轮数
  进了分母 ⇒ 转化区间每搪塞伤害 = 1 − (R−1)/(R+1) = 2/(R+1) > 1/R
  （全诚实基线 t_base ≡ 1.0，因为 tdhit 计「与真值一致」而非「confirm」）。
  **tdhit 结构性惩罚复问**，既不能用于 E1b 主判据，也不能用来评价转化
  的价值——转化价值只在 F1 通路可见（final_guess 采纳被搪塞后确认的
  类别）。读 E1b' 存档列时必须连带读转化率，否则会把「提问者在转化」
  误读成「搪塞伤害变大」。
- **dhit 可被「搪塞+转化+谎言」组合刷高**：表观命中照单全收。dhit 照报
  但不得用于 E1b。
- **转化率的分母是「被搪塞的问句数」**（去重后的问句），不是提问轮数——
  用轮数会把多次转化同一个问句计成多次机会。
- **Q-honest 的 ev 后缀状态未见过的副作用**（照实预备）：Q-honest 仅对
  诚实主持训练，其 Q 表没有 `;ev=` 后缀状态；面对搪塞主持时这些状态
  Q 全零、贪心退化到动作 0（可能反复问同一问句而「意外转化」）。
  这是**诚实基线的真实行为**，不是 bug——E2b 因此必须同时报
  「被搪塞问句复问率」与「已回答问句复问率」两个数，区分「学了转化」
  与「普遍更爱复问」。

## 6-C. 实验结果（2026-10-13 实测回填，服务器 172.16.222.99）

rounds=8 | H/Q episodes=2000/4000 | 共演 2 轮 | eval repeats=10 |

`web-proto/logs/marl_evade_report.md`（与 P2-A/A-7 报告同处 gitignored 的
`logs/`，不进 git；关键数已固化于本段与测试）。

**诚实结论（照实报，不凑正结果）**：

1. **E1b 在计数上 28/30 通过，但效应量可忽略**。训练主持每搪塞 F1 伤害
   落在 0.022–0.040，random-evader 恒为 0.0083；绝对增量 ≈ 0.014–0.032 F1，
   相对原 F1（≈0.10–0.15）不足 1/3 个标准差级别。**判据按预注册通过，但
   不能据此声称「搪塞轴带来了有实践意义的战略优势」**——这是与 B-1 同构的
   「统计显著、效果稀薄」。

2. **E2b 在 25/30 通过但不稳健**：提问者（Q-adv）在被搪塞问句上的复问率
   0.70–0.95，显著高过 Q-honest（0–0.43），说明**对抗训练确实让提问者
   学会了「被搪塞→复问逼出是/否」这一转化行为**。但 ε=0.01/0.6 出现 2–3 个
   seed 失效——失效 seed 里 Q-adv 的「已回答问句复问率」也偏低，印证 §6-B
   警告：转化 vs 普遍复问要分开看，本环境提问者本就爱复问，转化增益被稀释。

3. **E2b'（F1 鲁棒读数）无一致方向**：增量为 −0.025 ~ +0.051，噪声主导。
   与 E2b 结论一致——提问者学会了「形式上转化」，但转化带来的 F1 回收被
   其它轮的噪声抵消，未形成稳定增益。

4. **E3b ✅**：RL-questioner × evasive-host 与 mock-questioner × evasive-host
   两组端到端跑通（tdhit=0.125，n_evades 受配额约束），证明搪塞轴与真实
   引擎 TurtleSoupGame 接口闭合。

5. **失败模式 ①b（「有配额就搪塞」占优）部分显现但未坐实**：跨 ε 平均搪塞数
   1.31 / 配额 2，非恒满。结合 E1b 效应量可忽略，更可能的解释是——
   冻结期提问者不复问（DistinctRandom）→ 搪塞浪费 → Q 学习把搪塞降权，
   而非学会了「选择性搪塞」。这条需要后续拆 Phase H 后的搪塞分布才能定论。

**总体定位**：搪塞轴是 B-1「战略空间稀薄」结论的**第二次独立复现**。本环境
（关键词问答、8 轮、字符级 F1、表格 Q）对「欺骗」与「搪塞」两类战略都不提供
可稳健学习的信号。继续加训练量无意义；若要产生可学结构，方向仍是 §7 所列的
**环境丰富化**（LLM 主持措辞多变 / 提问者「质疑」动作 / 部分信息博弈），
而非本设置的参数或样本扩充。
